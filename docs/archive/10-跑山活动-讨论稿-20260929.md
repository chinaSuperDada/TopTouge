## 一、这份文档在说什么

一句话：把「活动」从一个**列表页**升级为**组队跑山 + 同行记录**的主玩法，并把「风险点」作为 P1 图层预留。

核心链路：`建队/加入 → 出发前风险清单 → 同行中（检查点打卡 + 队友状态）→ 结算报告卡 → 历史回放`。

定位：**角色为个人自驾 / 摩友，无车队组织者角色。**

## 三、已定方向（2026-09-29）

### D1 成绩口径 —— 房间即焚 + 分层可见（已定）

**判断依据**：高德显示实时车速不违规，是因为它做的是**安全辅助**（对比限速），而非「谁最快」的公开排名。所以敏感的不是数字，是**竞速化 + 公开化 + 排名化**三者叠加。结论：**不做公开竞速叙事**，但房间内可见时长/速度。

**「房间 = 可见性边界 + 生命周期边界」模型**：

| 数据 | 房间内（同行时） | 房间结束后 |
|---|---|---|
| 队友位置 / 心跳 / 实时状态 | 可见 | **即焚**（也恰好避开约束 B「无网实时位置是伪需求」） |
| 时长 / 速度 / 里程 | 可见（同行协作必需） | 房间内保留有限期，到期只留摘要 |
| **个人成绩** | — | **进本人履历，只有本人可见**（留存价值所在） |
| 对外分享卡 | — | 用户**主动生成** + **脱敏**（默认藏起终点、默认不出绝对速度） |

> **待确认**：「成绩即焚」是否连**个人履历**也焚？建议**否**——房间数据即焚，个人履历保留（回看自己跑过什么是核心留存）。

### D2 范围 —— 只融合「跑山」部分（已定）
不全局重做。把 MVP 里的**组队 / 同行记录**融入现有流程；进入跑山模块后再做子模块划分（§四）。重点是**把玩乐功能做流畅、体验做好**。

### D3 车型 —— 数据一起，交互分阶段（已定）
- **数据层本期放开 `auto / moto`**：`vehicleType`、排量、车牌；算法（难度/算分）两车型完全相同。
- **交互层本期按汽车优化**（大屏支架为主）；摩托交互（手套盲操、语音优先、停车打卡）标注**基础支持**，不阻塞 MVP。

### D4 平台 —— iPhone + 主流安卓优先（已定）
鸿蒙 Next 本期不考虑（预研与适配范围收窄）。

### D5 预研 —— M0 先行（已定）
后台定位 / 弱网打卡 / GPS 漂移 / 对时，四项真机预研结论出来再定最终形态。

## 四、融合方案（现有 → 新增）

**融合口子**：

```
路线详情「开始跑山」
   ├── 单人快速跑山   ← 现有流程，保留
   └── 组队跑山       ← 新增，进入房间

「跑山活动」tab  ← 组队的主入口（建队 / 加入 / 附近约跑）
```

**跑山模块内部子模块划分**（对应本目录后续文档）：

| 编号 | 子模块 | 内容 |
|---|---|---|
| 10 | 队伍 | 建房 / 加入 / 房间等待（队伍码、成员与车辆、准备度） |
| 11 | 同行 | 仪表盘 / 检查点打卡 / 队友状态（在线·信号丢失·失联） |
| 12 | 结算 | 报告卡 + 分享（脱敏） |
| 13 | 履历 | 历史记录 / 回放 / 详情（口径说明 + 数据质量标记） |

**体验流畅的四个着力点**（本轮重点）：

1. **建队→分享→进房一步直达**：分享卡点开直接进房间，不输码（队伍码只作兜底）。
2. **打卡无感**：自动打卡为主（进入半径），手动补卡兜底（断网/漂移时）。
3. **仪表盘扫一眼就懂**：夜间高对比、超大计时、下一检查点距离。
4. **结算即时可分享**：≤2s 生成，分享回流可埋点。

## 四、技术预研项（M0，1 周）

| 项 | 要验证什么 | 结论影响 |
|---|---|---|
| 后台/熄屏定位 | `wx.startLocationUpdateBackground` 在目标机型（含鸿蒙 Next）能否持续回调；类目是否批 | 决定「锁屏记录」是否承诺、是否走车机/手表兜底 |

| 对时 | 服务端对时 + 本地单调时钟在熄屏 30s 后的误差 | 决定计时口径能否成立 |

## 五、合规红线（上线前提）

1. **竞速叙事**：平台可能因「危险驾驶/竞速」拒审。其 Q1 自述建议「MVP 全部改成同行记录 / 路段用时，不做竞速榜与并列名次」——**建议采纳**。
2. **轨迹 = 敏感个人信息**（可关联个人行踪）：需要
   - 单独的《活动风险与数据授权》勾选；
   - 位置精度可选（精确 / 模糊）；
   - 分享卡片**默认隐藏起终点**（其 Q2）。
3. 与现有「原始轨迹 72 小时清空」的隐私承诺需衔接。
