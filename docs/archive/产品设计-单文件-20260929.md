# TopTouge 产品设计

> 本文档定义「长什么样、怎么用」——信息架构、页面、组件、交互与视觉。
> 「做什么」见 [需求规格说明书.md](./需求规格说明书.md)，技术实现见 [架构与技术设计.md](./架构与技术设计.md)，进度见 [项目管理.md](./项目管理.md)。

---

## 1. 产品定位与主张

**产品名**：TopTouge / 跑山路线。

**一句话介绍**：记录和分享跑山路线，跑完看分数和排名。

**目标用户**：喜欢开车跑山路的车友。核心诉求是「找一条好路 → 跑一趟 → 知道自己什么水平」。

**三条主张**（对应需求 R1–R3）：

- **成绩只出面子和位次**：结果页只有「综合评分」和「本路线第 N 名」，绝不出时间速度。跑山圈子里「几分几秒」容易引发攀比与危险驾驶，产品主动回避。
- **隐私可退**：可以只在本机记录，或者参与算分但原始轨迹 72 小时自动清除。
- **难度不糊弄**：星级由算法从轨迹算出，不靠人工填。

## 2. 信息架构

```
TopTouge
├── 跑山路线（tab）
│   ├── 活动位轮播（人工活动 + 算法位）
│   ├── 筛选：省市 / 难度 / 路型
│   ├── 排序：热度 / 长度 / 离我最近 / 最新
│   ├── 路线卡片列表
│   └── → 路线详情
├── 跑山活动（tab）
│   └── 活动列表（只要人工活动，含官方 / 版主来源）
├── ➕ 制作（tabBar 中间凸起按钮，弹方式选择）
│   ├── 搜索地点  → route-upload?mode=search
│   ├── 地图点选  → route-upload?mode=manual
│   └── 录制轨迹  → route-record
├── 我的（tab）
│   ├── 资料卡（头像 / 昵称 / 编辑入口）
│   ├── 三项统计：成绩 / 路线 / 收藏
│   ├── 我的成绩 / 我的路线 / 我的收藏
│   ├── 版主工作台（仅版主可见）
│   └── 设置
└── 流程页（非 tab）
    ├── 路线详情 → 开始跑山 → 跑山中 → 结果页
    └── 上传 / 录制 → 提交 → 路线详情
```

## 3. 关键页面设计

### 3.1 跑山路线（首页）

自上而下：**活动位轮播 → 筛选条 → 排序条 → 路线卡片列表**。

- 活动位：横向轮播，卡片用 `color` 做的兜底纯色块（无海报图时），角标显示 `tag`（本周最热 / 新路线 / 高难度）。点击按 `link` 跳详情。
- 筛选条：省市（省市联动）、难度（全部 / 简单…困难）、路型（山路 / 赛道 / 非铺装 / 公路）。
- 排序条：热度最高 / 长度最长 / 离我最近 / 最新收录。「离我最近」需要定位，**拿不到也照常可用**（退化为热度排序，不阻塞浏览）。
- 卡片：名称、距离、星级、弯道数、爬升、区域。

### 3.2 路线详情

顶部三个 tab：**路线主页 / 路线排名 / 评论**。

**路线主页**
- 地图：画出 `displayTrack` 轨迹线，起点 / 终点 / 途经点标记；已定位时显示蓝点。
- 难度面板（`difficulty-panel` 组件）：弯道数、急弯占比、爬升、距离、路宽、综合星级。
- 操作：收藏（心形，实心 / 空心由 `favorited` 决定）、分享（复制高德导航链接）、开始跑山。
- 未通过审核的路线给提示条（只对 `pending/rejected/deleted` 显示，`approved` 不占地方）。
- 相似路线区块：按重合度列出，`duplicate` 档位额外提示「可能是同一条路线」。

**路线排名**
- 成绩榜：名次、昵称头像、分数（**不显示用时**）。

**评论 / 路况**
- 两个区块：`comment-list`、`road-condition-list`，各带输入框，纯文字列表。

### 3.3 上传路线

两种采集方式，用 `mode` 参数进入：

| 模式 | 交互 | 适用 |
|---|---|---|
| `search` 搜索规划 | 搜索起终点 + 途经点（最多 5 个），高德自动规划路径 | 知道想去哪 |
| `manual` 地图点选 | 地图上依次点选生成坐标序列 | 知道具体走法 |

表单：路线名称、路宽（窄 / 中 / 宽 下拉）、路型。提交前**自动查重**（`check-duplicate`），命中 `duplicate` 时提示用户确认。提交成功后直接跳详情页，无强制审核等待页。

地点搜索候选是**浮层**，需按键盘高度上移避免遮挡；搜过 / 选过的地点存入本地历史（`placeHistory`），下次点搜索框直接选。

### 3.4 跑山流程（跑山中最关键）

```
详情页「开始跑山」
   ↓
数据模式选择（ActionSheet，默认第一项）
   ① 参与算分（原始轨迹 72 小时后自动清除）
   ② 仅本机记录（不参与算分）
   ↓
跑山中页
   · 地图：参考路线（进页面就画）+ 实际轨迹（边跑边画）
   · 实时统计：已用时长、已采集点数、距离
   · 距终点 < 300m 时提示「距终点 xxx m」
   · 暂停 / 继续；手动结束
   · 进入终点区域 → 震动 + toast「已到达终点」→ 自动结束
   ↓
   ├─ 参与算分 → 提交后端 → 结果页
   └─ 仅本机   → 本机统计，不发请求
```

**边界处理**：
- 轨迹点 < 2 时结束 → 提示「轨迹太短，无法计入成绩」，可选「继续跑」。
- 定位权限被拒 → 引导 `openSetting`（只有这里能改这个开关）。
- 采样节流：位移 < 8m 不记点（避免等红灯堆重复点）；点数上限 10000（防定位漂移）。

### 3.5 结果页

**只有两个数字**：

```
       782
     综合评分
   本路线第 8 名
  [ 返回路线详情 ]
```

任何时间、速度、轨迹数值都不出现（需求 R1）。

### 3.6 我的

资料卡（头像 + 昵称 + 编辑入口）→ 三项统计（成绩 / 路线 / 收藏）→ 功能入口列表（我的成绩 / 我的路线 / 我的收藏 / 版主工作台[仅版主] / 设置）。

未设昵称时显示由 openid 派生的稳定短标识（如「车友 3072」），**不显示原始 openid**。

## 5. 导航与视觉

### 5.1 自定义 tabBar

`app.json` 里 `tabBar.custom = true`，结构为 **跑山路线 / 跑山活动 / ➕ / 我的**：

- 四个位置，中间是**凸起的加号**（`create-btn`），点击弹出制作方式（搜索地点 / 地图点选 / 录制轨迹），**不切换页面** —— 用户选完仍停在当前 tab。
- 左右两个 tab 用 `wx.switchTab` 切换（目标页在 `tabBar.list` 里，用 `navigateTo` 会报错）。

> ⚠️ **样式颜色必须写死，不能用 CSS 变量。**
> `custom-tab-bar` 渲染在 `page` 标签之外，拿不到 `app.wxss` 里定义在 `page` 选择器下的变量。用 `var()` 会**静默失效**——表现为深色底上元素变黑，看起来像「没渲染」，极难排查。改配色时手动与 `styles/tokens.wxss` 同步。

### 5.2 配色（`styles/tokens.wxss`）

参考设计取色：**接近纯黑的深色底 + 亮青蓝 `#0c9cfc` 为主强调 + 草绿 `#6c9c3c` 为辅**。强调色在原参考图里只占 6.5% 像素，是点缀用法，**不要大面积铺**。

| 类别 | 变量 | 值 |
|---|---|---|
| 背景（三级递进） | `--bg-base` / `--bg-surface` / `--bg-elevated` / `--bg-inset` | `#080808` / `#141414` / `#1c1c1c` / `#000000` |
| 文字 | `--text-primary` / `--text-secondary` / `--text-tertiary` | `#f8f8f8` / `#b8b8b8` / `#6e6e6e` |
| 主强调 | `--accent` | `#0c9cfc` |
| 次强调 | `--accent-alt` | `#6c9c3c` |
| 功能色 | `--success` / `--danger` / `--warn` | `#6c9c3c` / `#e5484d` / `#d4a72c` |
| 星级 | `--star` / `--star-empty` | `#0c9cfc` / `#2a2a2a` |

### 5.3 视觉规范

- **圆角**：`--radius-sm/md/lg/pill` = 10 / 18 / 26 / 999 rpx。
- **间距**：8 的倍数体系（`--space-1`…`--space-6` = 8…56 rpx）。
- **字号**：整体比常规移动端**偏大**——深色底上小字更难读，且核心信息是数字。`--fs-caption`…`--fs-hero` = 24…104 rpx。
- **数据高亮**：关键数字用纯白 `#ffffff`，与正文 `#f8f8f8` 拉开一丝差别。

## 6. 文案规范

### 6.1 用户文案（必须是人话）

| 场景 | 文案 |
|---|---|
| 网络不通 | 网络开小差了，请稍后再试 |
| 服务端出错 | 服务暂时不可用，请稍后再试 |
| 未检测到完整路线 | 未检测到完整完成路线，本次不计入排名 |
| 轨迹太短 | 还没采到足够的轨迹点，无法计入成绩。 |
| 需要定位权限 | 开启后才能在地图上看到你的位置、使用「离我最近」排序。 |
| 上传成功 | （直接跳详情页，不弹无信息量的成功提示） |

### 6.2 禁止出现的文案

**任何技术细节都不能出现在用户界面**：`errMsg`、HTTP 状态码、错误码、URL、堆栈、域名白名单提示等。这些进 `client_errors` 表给管理员看。

### 6.3 审核状态文案

只对「未通过」的状态给提示，`approved` 不显示标签：

| 状态 | 文案 |
|---|---|
| `pending` | 这条路线正在审核，通过后才会出现在公开列表 |
| `rejected` | 这条路线已被下架：{理由} / 这条路线已被下架 |
| `deleted` | 这条路线已被删除 |

## 7. 交互约定（全局）

- **加载态**：列表页首次加载显示骨架 / 占位；下拉刷新。
- **空态**：无数据时给一句说明，不留白屏。
- **错误态**：页面级失败展示白话 + 重试按钮，不弹技术细节。
- **防连点**：提交类按钮（收藏、上传、评论）进行中禁用并显示 loading。
- **定位失败不阻塞**：拿不到定位时功能降级但可用（浏览、地图都不受影响）。
- **tabBar 选中态同步**：各 tab 页 `onShow` 里同步 `selected`（自定义 tabBar 不会自动同步）。
