# 模块 03 · 上传与录制

> 覆盖：上传路线（搜索规划 / 地图点选两种模式）、录制轨迹生成路线、上传前查重、地点搜索历史、导航分享链接。
> 对应后端：`routes.router` → `routeService`。

---

## 1. 入口

从底部 tabBar 中间的 **➕** 按钮进入，弹出制作方式选择：

| 方式 | 跳转 |
|---|---|
| 搜索地点 | `route-upload?mode=search` |
| 地图点选 | `route-upload?mode=manual` |
| 录制轨迹 | `route-record` |

---

## 2. 上传路线（`route-upload`）

两种采集方式，用 `mode` 参数区分：

| 模式 | 交互 | 适用 |
|---|---|---|
| `search` 搜索规划 | 搜索起点 / 终点 + 途经点（最多 5 个），高德自动规划路径 | 知道想去哪 |
| `manual` 地图点选 | 在地图上依次点选生成坐标序列 | 知道具体走法 |

### 2.1 表单

路线名称、路宽（窄 / 中 / 宽 下拉）、路型（山路 / 赛道 / 非铺装 / 公路）。

### 2.2 提交前查重

调用 `POST /api/routes/check-duplicate`，命中 `duplicate` 档位时提示用户确认，避免同一条山路被反复上传。

### 2.3 提交后

成功后**直接跳转路线详情页**，不弹成功提示、无强制审核等待页。公开路线会进入待审状态（详情页会显示「正在审核」提示条，见模块 02 §2.4）。

### 2.4 地点搜索

- 候选列表是**浮层**，需按键盘高度上移避免遮挡。
- 搜过 / 选过的地点存入**本地历史**（`placeHistory`），下次点搜索框直接选。历史只存本机，不上传。

---

## 3. 录制轨迹（`route-record`）

实时记录行驶轨迹，结束后保存为路线。与跑山页（模块 04）共用采集逻辑，但**目的是生成路线而非记成绩**。

采集节流（与跑山页一致）：

- 位移 < **8m** 不记点（避免等红灯堆重复点）。
- 点数上限 **10000**（防定位漂移）。

---

## 4. 导航分享链接

分享按钮 → 把高德导航链接**复制到剪贴板**（`utils/amapShare.js` 构造 `m.amap.com/navigation/carmap` 链接）。

**为什么是复制链接而不是直接跳转**：这条路能把起终点和全部途经点都带上。用户粘贴到聊天窗口发送，微信识别到 `amap.com` 链接会渲染成高德卡片，点击即唤起高德打开完整路线。

**试过但不可行的方案**（别再走一遍）：

- `MapContext.openMapApp` —— 参数只有一个点，**没有途经点**。
- `wx.navigateToMiniProgram` 跳高德小程序 —— 高德没有独立地图小程序。
- `web-view` 打开 amap.com —— 微信不允许把高德域名配成业务域名。

**闭环路线**（起点 = 终点）走外部导航无意义，页面会提示；导航 URL 生成时截掉后半程、把最远点当终点。

---

## 5. 依赖与约束

- 依赖：模块 01（全局框架）、高德 SDK（搜索 / 规划 / 逆地理编码）。
- 被依赖：模块 02（提交后跳详情）。
- 约束：提交的坐标序列经后端校验（≥2 点、≤5000 点、经纬度合法），派生指标**全部由后端算**。
