# 模块 04 · 跑山与算分

> 覆盖：跑山中最关键的「开始 → 采集 → 结束 → 结果」全流程、数据模式选择、到达判定。
> 对应后端：`runs.router` → `runService`。
> 这是**产品的核心链路**，改动需谨慎并重点验证。

---

## 1. 流程总览

```
路线详情「开始跑山」
   ↓
数据模式选择（ActionSheet，默认第一项）
   ① 参与算分（原始轨迹 72 小时后自动清除）
   ② 仅本机记录（不参与算分）
   ↓
跑山中页
   ↓
   ├─ 参与算分 → 提交后端 → 结果页
   └─ 仅本机   → 本机统计，不发请求
```

---

## 2. 数据模式选择

开始前用 `wx.showActionSheet` 单选，**默认第一项**：

1. **参与算分（原始轨迹 72 小时后自动清除）** —— 多数人想要成绩和排名。
2. **仅本机记录（不参与算分）** —— 隐私敏感用户：轨迹不上传、不算分、不产生服务端记录。

---

## 3. 跑山中页（`run`）

### 3.1 地图

同时画两条线：

- **参考路线**（要跑的目标）—— 进页面就画，不能等采到点才画。
- **实际轨迹**（已经跑的）—— 开始后逐渐出现。

### 3.2 实时统计

已用时长、已采集点数、距离。

### 3.3 控制

- 暂停 / 继续：暂停时长不计入成绩（结算时扣除）。
- 手动结束。
- 距终点 < **300m** 时提示「距终点 xxx m」。

### 3.4 到达判定与自动结束

每采到一个点就判断是否进入终点区域（欧氏近似，见架构文档 §6.3）：

- 进入终点区域 → `wx.vibrateShort` + toast「已到达终点」→ **自动结束并提交**。

### 3.5 边界处理

| 情况 | 处理 |
|---|---|
| 结束时尚不足 2 个点 | 提示「轨迹太短，无法计入成绩」，可选「继续跑」或「结束」 |
| 定位权限被拒 | 引导 `wx.openSetting`；无法开始记录时给明确说明 |
| 位移 < 8m | 不记点（避免等红灯堆重复点） |
| 点数达 10000 | 不再累积（防定位漂移） |

---

## 4. 结果页（`run-result`）

**只有两个数字**：

```
       782
     综合评分
   本路线第 8 名
  [ 返回路线详情 ]
```

**任何时间、速度、轨迹数值都不出现**（主张 R1）。这是硬约束——真机验证时必须确认界面上不存在时长 / 速度。

---

## 5. 数据模式与后端的对应

| 模式 | 后端行为 |
|---|---|
| `ranked` | 落库、算分、排名；原始轨迹 72 小时后清空，成绩保留 |
| `local_only` | **不落库直接返回**；只在本机展示统计 |

轨迹匹配失败（没跑完整路线）时，后端返回「未检测到完整完成路线，本次不计入排名」——前端展示这句白话。

---

## 6. 依赖与约束

- 依赖：模块 01（全局框架）、模块 02（从详情进入）、高德 SDK、**前后端镜像几何算法**（`utils/runGeo.js` ↔ `server/src/geo/`）。
- 被依赖：模块 07（我的成绩）。
- 约束：
  - **前端镜像算法必须与后端一致**，否则会出现「前端说到终点了、后端说不匹配」。改一侧必须同步另一侧。
  - 结果页不得出现时间 / 速度。
