# 模块 10 · 跑山活动

> 覆盖：活动列表（筛选 / 排序）、活动详情与申请加入、创建活动（公开 / 私有）、凭房间号 + 密码加入。
> 定位：**车友自发组织跑山活动** —— 约人、定集合点与路线、管人数。
> 与「运营活动位」（[06-活动位.md](./06-活动位.md)，平台 / 版主发布）是两回事：那个是官方内容位，这个是用户自己发起。
>
> ⚠️ **字段与规则仍可能调整**；已实现的前端见 §9。
>
> **本轮范围**：只做「活动管理」——约人、定集合点与路线、管人数。
> **不做**：同行记录（仪表盘 / 打卡 / 结算 / 轨迹回放）、风险图层 —— 见 §7。

---

## 1. 定位与范围

用户可自发创建跑山活动，按可见性分两类：

| 类型 | 谁能看到 | 怎么加入 |
|---|---|---|
| **公开活动** | 出现在活动列表，所有人可见 | **申请加入**，需**组织者同意** |
| **私有活动** | 不出现在列表 | 凭**房间号 + 4 位数字密码**加入；也支持分享链接直接进入 |

**与现有模块的关系**：

- **复用路线库**（[02-路线库.md](./02-路线库.md)）：创建活动时可选择已有路线。
- **复用用户资料 / 车辆**（[07-我的与资料.md](./07-我的与资料.md)）：发起人信息、我的车辆。
- **与运营活动位区分**（[06-活动位.md](./06-活动位.md)）：本模块是 UGC 活动，运营活动位是官方内容。
- **后续可衔接**「同行记录」（仪表盘 / 打卡 / 结算）—— 本轮先不做，见 §7。

## 2. 页面清单

| 页面 | 实际路径 | 说明 |
|---|---|---|
| 活动列表 | `pages/activity/index/index` | **第一页**（tabBar「跑山活动」）：筛选 + 排序 + 卡片列表 + 右下角「＋」 |
| 活动详情 | `pages/activity/detail/detail` | 点卡片进来；活动信息 + 申请加入 |
| 创建活动 | `pages/activity/create/create` | 「＋ → 创建跑山活动」；表单 + 公开 / 私有 |
| 加入房间 | `pages/activity/join/join` | 「＋ → 加入房间」；输房间号 + 密码 |
| 活动房间 | `pages/activity/room/room` | 创建 / 加入后的**主页面**：活动信息、房间号密码（组织者可见）、待审批、成员 |

> **「房间信息」不单独做页面** —— 它就是「活动房间」页里组织者可见的一块（房间号 + 密码 + 复制/分享），
> 并且在「我的活动 → 我发起的」里可随时翻出来。

### 2.1 跳转关系

```
活动列表（tab）
 ├─ 点卡片 ──► 活动详情 ──(申请加入 / 已加入)──► 活动房间
 └─ ＋ ──► 创建活动 ──(成功)──► 活动房间（带 created=1，顶部提示"活动已创建"）
      └─► 加入房间 ──(成功)──► 活动房间
我的活动（列表页「我的活动」分段）──► 活动房间
```

## 3. 页面设计

### 3.1 活动列表（第一页）

**顶部**：标题「跑山活动」+「附近 N 个活动」。

**筛选条**（横向）：

| 筛选项 | 说明 |
|---|---|
| 地点 | 城市 / 区域，或「离我最近」的范围 |
| 时间段 | 今天 / 本周 / 本月 / 自定义 |
| 难度 | 休闲 / 进阶 / 硬核（待定是否复用路线星级） |
| 排序 | **离我最近** / **人数** / **时间**（最新 / 最早）等 |

**活动卡片**，每条显示：

- 发起人头像 + 昵称
- 活动名称
- 集合时间 + 集合地点
- 路线信息（未指定路线时显示「仅定位集合点」）
- 人数 `已加入 / 上限`
- 难度标签
- 距我多远

**右下角**：悬浮「＋」按钮 → 弹出**创建活动 / 加入房间**两个选项。

> 创建和加入都属低频操作，不占主导航位，挂在「＋」下最合适。

**分段**：列表页顶部有「全部活动 / 我的活动」两个分段。我的活动 = 我发起的 + 我参加的。

### 3.2 活动详情

- 活动信息：名称、发起人、集合时间、集合地点、路线信息、人数、已加入成员（头像列表）。
- **全队阅读**说明（创建时配置的文案）。
- **公开活动**：底部「申请加入」→ 提交后变为「已申请 · 等待组织者同意」。
- **私有活动**：不在列表出现；从分享链接进来直接进入，或凭房间号 + 密码加入。

### 3.3 创建活动

**字段**：

| 字段 | 说明 |
|---|---|
| 活动名称 | 必填 |
| 集合时间 | 必填 |
| 集合地点 | 地图选点 / 搜索 |
| **路线信息** | 二选一：**选择已有路线** / **不指定路线，只发一个定位** |
| 活动人数 | 上限，如 5 / 8 / 20 |
| 我的车辆 | 来自用户资料 |
| **全队阅读** | 系统生成**默认提示文案**，**创建者可自定义编辑** |

**可见范围**：

- **公开**：出现在列表，谁都能申请。
- **私有**：创建后生成**房间号 + 4 位数字密码**。

默认「全队阅读」文案（可编辑）：

> 本活动只做同行记录与路况提示，不提供任何竞速、封闭道路或安全保障。参加即表示已阅读并同意：遵守交通法规，服从组织者安排，安全自负。

### 3.4 活动房间（创建 / 加入后的主页面）

- 活动信息卡（集合时间 / 地点 / 路线 / 人数）。
- **房间号 + 密码**（仅组织者可见，带「复制全部」「分享链接」）—— 这就是「房间信息」，不单独做页面。
- **待同意**列表（仅组织者）：显示申请人昵称、车辆，一键同意 / 拒绝。
- **成员**列表：昵称、车辆、是否就绪。
- 底部「开始跑山」→ 跳现有单人记录流程 `pages/run/run?routeId=`；活动没指定路线时提示无法记录。
- **各跑各的**：这里不做「全队一起发车」，到场集合后各自出发。

### 3.5 加入房间（私有）

- 输入**房间号 + 4 位密码**。
- 校验通过即加入。
- 输入错误时提示**不区分是房间号还是密码错**（防爆破）。

## 4. 关键规则

| 规则 | 当前设定 | 待定 |
|---|---|---|
| 公开活动加入 | 申请 → 组织者同意 | 是否支持自动通过？组织者拒绝要不要理由？ |
| 私有活动加入 | 房间号 + 4 位密码 | 房间号 6 位？密码是否可刷新？有效期？ |
| 分享链接 | 点开直接进房间 | token 机制、是否过期、是否绑定用户 |
| 人数上限 | 达到后不可再加入 / 申请 | 满员后是否进候补？ |
| 活动状态 | — | 待定：未开始 / 进行中 / 已结束 / 已取消 |

## 5. 数据模型（概念级）

> 字段级设计待与后端一起定（见 [../架构与技术设计.md](../架构与技术设计.md)）。

```
Activity        活动：名称、集合时间、集合地点、路线(可空)、人数上限、
                可见性(public/private)、全队阅读文案、发起人、状态
ActivityMember  成员：活动 + 用户、角色(组织者/成员)、车辆、加入时间
JoinRequest     公开活动的加入申请：活动 + 用户 + 状态(待同意/同意/拒绝)
Room            私有房间：活动、房间号、密码、分享 token
```

**与路线的关系**：`Activity.routeId` 可空 —— 空表示「仅定位集合点」。

## 9. 已实现的前端（2026-09-29）

页面在 `miniprogram/pages/activity/`，数据层 `miniprogram/utils/activityMock.js`（**mock**，签名与将来接口一致）。
「跑山活动」tab 已指向新列表页；自定义 tabBar 同步更新。

| 页面 | 文件 | 说明 |
|---|---|---|
| 列表 | `index/index` | 全部 / 我的分段、筛选排序、卡片、「＋」 |
| 详情 | `detail/detail` | 申请加入 / 已加入 / 我发起 的多态主按钮 |
| 创建 | `create/create` | 名称 / 日期时间 / 地点 / 路线或定位 / 难度 / 人数 / 车辆 / 全队阅读 / 公开私有 |
| 加入房间 | `join/join` | 房间号 6 位 + 密码 4 位，错误不区分提示 |
| 房间 | `room/room` | 房间号密码（组织者）、待审批、成员、开始跑山 |

**演示用 mock**：房间号 `482913` / 密码 `6628`；活动 `1001` 的发起人是当前用户（可见房间号与待审批）。

### 9.1 后端接口设计（**待实现，先冻结契约**）

页面只依赖 `activityMock` 的函数名，接后端时把函数体换成 `api.get/post` 即可，**页面零改动**。

| 函数 | 方法 | 路径 | 说明 |
|---|---|---|---|
| `listActivities` | GET | `/api/activities` | 参数 `province/city/timeRange/difficulty/sort/lat/lng` |
| `getActivity` | GET | `/api/activities/:id` | 详情，含成员、我的状态 |
| `createActivity` | POST | `/api/activities` | 创建；私有返回 `roomNo` / `password` |
| `applyJoin` | POST | `/api/activities/:id/join-requests` | 公开活动申请加入 |
| `reviewJoin` | POST | `/api/activities/:id/join-requests/:reqId/review` | 组织者同意 / 拒绝 |
| `joinByRoom` | POST | `/api/activities/join` | 房间号 + 密码加入 |
| `joinDirect` | POST | `/api/activities/:id/join` | 分享链接直接加入 |
| `getRoom` | GET | `/api/activities/:id/room` | 房间：成员、待审批（组织者）、房间号密码（组织者） |
| `listMyActivities` | GET | `/api/me/activities` | 参数 `role=all/joined/organized` |

**数据表**（详见 [../架构与技术设计.md](../架构与技术设计.md)）：

```
activities            活动主表（含 visibility、room_no、password、notice 等）
activity_members      成员（role: organizer/member、vehicle、ready）
activity_join_requests 申请（status: pending/approved/rejected）
```
