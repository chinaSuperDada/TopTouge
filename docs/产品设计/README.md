# 产品设计（模块化）

> **本目录是「设计先行」的落点。** 开发流程固定为：**先改这里的产品设计 → 再动代码**。
> 每个模块一个文件，改需求 / 加功能时**只动对应模块的文件**，改完提交 git，每次变更可追踪。

---

## 一、开发流程（设计先行）

```
① 改产品设计（本目录对应模块）──▶ ② 评审 / 定稿 ──▶ ③ 按设计写代码 ──▶ ④ 单测&自验 ──▶ ⑤ 真机 ──▶ ⑥ 部署 ──▶ ⑦ 发布
```

- **先设计后实现**：任何界面 / 交互 / 文案的改动，先在对应模块文档里写清楚，再动代码。
- **模块化切分**：一个模块一个文件。开发某个模块时，只改那个文件，避免多人编辑同一份大文档冲突。
- **git 追踪**：文档与代码同仓库，每次变更都有提交记录。**改设计 → 提交 → 再改代码 → 提交**，两次提交的关联在提交信息里写清（如「设计：路线库加 XX 筛选」）。
- **模块内「变更记录」**：每个模块文件末尾有一张变更记录表，记谁在什么时候改了什么。
