# 如何继续开发

> 给接手的人（或未来的自己）：怎么找到上下文、怎么进工作区、怎么恢复会话。
> 一句话原则：**重要的东西都写进 `docs/` 并提交了**，所以哪怕会话丢了、机器换了，看文档也能接上。

---

## 一、先看文档（永远从这里开始）

| 想知道 | 看 |
|---|---|
| 这个产品做什么 | [需求规格说明书.md](./需求规格说明书.md) |
| 某个页面长什么样、怎么用 | [产品设计/](./产品设计/)（按模块拆分，改哪个模块看哪个文件） |
| 怎么实现、接口怎么定 | [架构与技术设计.md](./架构与技术设计.md) |
| 谁在做、做到哪、下一步 | [项目管理.md](./项目管理.md) |
| 历史决策与废弃方案 | [archive/](./archive/)（归档，只看不改） |

**开发流程是固定的七步**（见 [项目管理.md](./项目管理.md)）：
需求提出 → 产品设计 → 代码实现 → 单测自验 → 真机验证 → 部署验证 → 发布。

**「设计先行」是硬规矩**：改任何界面 / 交互 / 文案，**先在 `docs/产品设计/` 对应模块里改，提交，再动代码**。

## 二、工作区：一个任务一个 worktree

仓库共用一份 `.git`，但可挂多个工作目录（worktree），每个检出不同分支、互不干扰。
**不要多个人 / 多个会话往同一个目录里写** —— 之前就因为这样，两个会话的提交堆到了同一条分支上。

### 看现在有哪些工作区

```bash
cd ~/workspace/github/TopTouge
git worktree list
```

### 新建一个（每个新任务）

```bash
git fetch origin
git worktree add -b feat/<任务名> ../TopTouge-<任务名> origin/main
cd ../TopTouge-<任务名>
```

### 用完删掉

```bash
cd ~/workspace/github/TopTouge
git worktree remove ../TopTouge-<任务名>     # 有未提交改动时加 --force
```

> ⚠️ **删之前一定先提交 + 推送**。worktree 里未提交的改动，一删就没了。

### 每个新 worktree 都要单独处理的东西（被 gitignore，不共享）

| 东西 | 要做什么 |
|---|---|
| `server/node_modules/` | `cd server && npm install` |
| `server/.env` | `cp` 一份过来（含数据库连接，不入库） |
| `miniprogram/project.private.config.json` | 微信开发者工具打开该项目时自动生成 |
| `tools/e2e/node_modules/` | 要跑 e2e 才装 |

**微信开发者工具**：一个 worktree 就是一个独立项目，要**分别导入各自的 `miniprogram/` 目录**（用不同窗口），别用旧窗口。

## 三、恢复 Claude 会话

会话历史是**按「项目路径」存的**，不是按 worktree 存。所以：

- 某个目录下的会话，记录在 `~/.claude/projects/<把路径的 / 换成 ->/` 里，**一个会话一个 `.jsonl`**。
- 主仓库 `~/workspace/github/TopTouge` 的会话就在 `~/.claude/projects/-Users-xingwu-wang-workspace-github-TopTouge/`。

### 怎么恢复

```bash
cd ~/workspace/github/TopTouge     # ← 关键：要在会话所属的那个目录里启动
claude --resume                     # 列出所有会话，上下键选（有预览）
claude -c                           # 直接继续最近一次
claude --resume <session-id>        # 按 ID 精确恢复
```

会话 ID 就是 `.jsonl` 的文件名（去掉后缀）。会话里也可以直接敲 `/resume` 切。

> **注意**：会话挂在哪个项目路径下，就要在**那个路径**里启动才能列出来。
> 如果会话是在主仓库目录启动的，就得在主仓库目录里 `claude --resume`，
> 从 worktree 目录启动**列不出来**。

### 恢复会话 ≠ 回到 worktree

两码事。恢复会话后，如果要在某个 worktree 里干活，`cd` 进去即可：

```bash
cd ~/workspace/github/TopTouge/.claude/worktrees/<名字>
```

### 会话丢了怎么办

不要紧 —— **决策都落在 `docs/` 里并提交了**。从[项目管理.md](./项目管理.md) 的任务表、
[产品设计/](./产品设计/) 的变更记录，就能看出做过什么、为什么这么做。

## 四、提交规范

- 文档与代码**同仓库**，每次改动都有提交记录。
- **改设计 → 提交 → 再改代码 → 提交**，两次提交的关联写在提交信息里（如「设计：路线库加 XX 筛选」）。
- 当前在 `main` 之外的开发，**先拉分支**，再提 PR。
- 提交信息末尾带：

  ```
  Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>
  ```

## 五、本地起服务

```bash
# 后端
cd server
npm install
cp .env.example .env    # 不填数据库则用内存模式
npm run dev             # http://localhost:3000
npm test                # 强制走内存，不碰真库

# 小程序
# 微信开发者工具打开 <worktree>/miniprogram
# 详情 → 本地设置 → 勾选「不校验合法域名、web-view、TLS 版本以及 HTTPS 证书」
```

后端地址切换见 [../README.md](../README.md)：开发版走本地直连，体验版 / 正式版走云托管。
