## 1. 项目概述

**一句话**：面向车友的跑山路线分享 + 成绩记录微信小程序。

**核心链路**：找路线 → 跑一趟 → 看分数和排名，附带轻量社区（评论 + 路况）与路线管理（上传 / 录制 / 收藏 / 审核）。

### 1.1 范围（已定）

| 项 | 决定 |
|---|---|
| 车型 | 本次**只支持汽车**，代码预留 `vehicleType` 便于扩展 |
| 平台 | 微信小程序原生开发（JS + WXML + WXSS） |
| 路线初始数据 | 3 条手写 mock 路线（含 GPX 坐标序列），同时支持用户上传 |
| 登录 | **不做账号系统**，固定测试 `userId` |

### 1.2 三条设计原则（贯穿全部需求）

- **R1 成绩只出面子和位次**：结果页只有「综合评分」和「本路线第 N 名」，**不出现用时、速度或任何原始数值**。
- **R2 隐私可退**：跑山前可选「参与算分」或「仅本机记录」；参与算分的原始轨迹 72 小时后自动清空，成绩保留。
- **R3 技术细节不给用户看**：用户只看到白话提示，技术细节上报后台给管理员。

| 角色 | 说明 | 权限 |
|---|---|---|
| 游客 / 用户 | 微信用户，无账号系统，身份由 openid 识别 | 浏览、上传路线、跑山、评论、路况、收藏、编辑本人资料 |

| 管理员 | 平台运营 | 查 `client_errors` 排障；平台级活动与全局数据（通过数据库直接操作） |

| R-06 | 轨迹匹配 | 见 §5.3，闭环 / 非闭环两种情况分别处理 | 匹配失败时明确提示「未检测到完整完成路线，本次不计入排名」 |

## 4. 数据需求

### 4.1 核心实体

**Route（路线）**
```
id, name, vehicleType, distanceMeters
startPoint { lat, lng, radiusMeters }, endPoint { lat, lng, radiusMeters }
waypoints [ { name, lat, lng } ]
referenceTrack [ { lat, lng, altitude } ]   ← 全量，难度计算用
displayTrack   [ { lat, lng, altitude } ]   ← 抽稀，地图绘制用
uploadedBy（userId 或 "system"）
curveCount, sharpCurveRatio, elevationGainMeters, roadWidth(narrow/medium/wide)
difficultyStars(1-5), province, city, roadType, heat, pinned
visibility(public/private), reviewStatus(pending/approved/rejected/deleted)
createdAt
```

**RunRecord（跑山记录）**
```
id, userId, routeId, vehicleType
rawTrackPoints [ { lat, lng, altitude, speed, timestamp } ]
status(recording/completed/invalid)
totalTimeSeconds   ← 内部字段，不对外
score(0-1000), rank(该路线内名次)   ← 对外
createdAt, expiresAt(createdAt + 72h)
```

**Comment / RoadCondition**
```
id, routeId, userId, content, createdAt
```

**Banner（活动位）**：`source(algorithm/platform/moderator), title, subtitle, tag, image, color, link, province, city, startsAt, endsAt, priority, status(draft/published/offline)`。

**Moderator（版主）**：`userId, province, city, permissions, grantedBy, createdAt`。

**User（用户资料）**：`userId, nickName, avatar(base64)`。

### 4.2 数据约定

- **坐标系**：全链路 **GCJ-02**（高德）。不做 WGS-84 转换——阶段内没有跨源数据。
- **轨迹存储**：`altitude` 允许缺省（地图点选拿不到海拔），缺失按 0 处理。
- **地区**：`province/city` 允许为空（定位失败时）。

## 5. 算法需求

算法为纯函数、可单测；前端跑山时需镜像实现（见架构文档）。阈值集中在 `server/src/constants.js` 便于调参。

### 5.1 难度计算

| 项 | 规则 |
|---|---|
| 距离 | Σ haversine(p[i], p[i+1]) |
| 转向角 | 相邻三点 bearing 差，归一化到 (-180, 180] |
| 弯道数 | 转向角 > **30°** 记为转向点，连续转向点合并为一个弯道区间，区间数即弯道数 |
| 急弯占比 | 弯道区间内峰值角 > **60°** 记为急弯，急弯数 / 弯道数 |
| 爬升 | Σ max(0, alt[i+1] − alt[i])，不是最大减最小 |
| 星级 | 「每公里弯道数」与「每公里爬升」各归一化到 [0,1]，**取较大者** × 5 四舍五入，夹到 1–5 |

> **对任务书的两处偏离（已定）**：
> 1. 星级取「较大者」而非「取平均」——取平均会反直觉：弯道密集的平路加一点爬升，平均分反被拉低，等于「有坡让路变简单了」。语义应为「难度取决于最突出的维度」，对驾驶者宁可高估不可低估。
> 2. 爬升为 0 时该维度不参与——上传页是地图点选，拿不到海拔，若不排除，所有上传路线都会被当成平坦压到低星，失去区分度。

### 5.2 路线重合度

- **判定方法**：沿一条轨迹等距采 50 点，逐点算到另一条的最短距离，小于 **50m** 算命中，得覆盖率；两条互算后**取较小值**。
- **为什么不用几何中心**：跑山路线大量是环形，环的重心在山体内部、离路线几公里，比中心会失效。
- **为什么取 min 不取平均**：处理「短路线套在长路线里」——2km 的一段恰好是 20km 路线的一部分时，取 min 明确判为「不是同一条」。
- **档位**：`duplicate ≥ 0.85 / similar ≥ 0.6 / partial ≥ 0.3 / distinct`。

### 5.3 跑山轨迹匹配

**闭环路线**（起终点相距 ≤ 起点半径，跑山常见形态）
> 不能取「第一次进终点」——那会得到出发瞬间的下一个采样点、用时接近 0。
> 正确做法：找**离起点最远的点**（绕到最远处），再找它之后第一次回到起点区域的时刻。

**非闭环路线**（起点 ≠ 终点）
> 第一次进起点区域 → 之后第一次进终点区域，取时间差。
> 同样不能简单取首尾点，用户可能从半路开始记录或跑完又溜达。

匹配不到完整路线 → 返回错误「未检测到完整完成路线，本次不计入排名」。

### 5.4 算分与排名

- `score = 用时百分位 × 1000`（四舍五入取整）。
- 该路线**没有历史成绩**时，不给 0 分（用户会以为系统坏了）：按难度给保底分——1 星 500 分起步，每星 +50。
- 排名 = 比自己快的人数 + 1，**查询时现算**（`rank_no` 只在「刚跑完」结果页用）。

### 5.5 轨迹过期清理

- 每小时执行一次，`expiresAt < now` 的记录 `rawTrackPoints` 置空，**不删整条记录**，`score`/`rank` 保留。
- 这是 **R2 隐私承诺**的技术兑现：跑完 72 小时后原始轨迹消失，成绩仍在榜上。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 列表接口不返回轨迹（响应体控制在几十 KB 内）；详情默认返回抽稀轨迹；重合度精算先用起点半径粗筛 |
| 隐私 | 原始轨迹 72 小时清空；「仅本机记录」不产生服务端数据；地点搜索历史只存本机 |
| 可用性 | 定位失败不阻塞浏览；网络抖动自动重试（2 次）；数据库故障时服务降级启动不崩溃 |
| 可维护性 | 分层清晰（routes / services / repositories / geo）；数据源可切换；错误响应结构统一 |
| 可测试性 | 几何与算分逻辑为纯函数，重点单测；测试强制走内存数据源 |
| 兼容性 | 小程序原生，支持云托管；开发 / 体验 / 正式版自动切换后端 |

## 7. 明确不做的部分

- 不做登录 / 账号系统
- 不做独立的多人可浏览排行榜 / 榜单页面（排名只在跑完结算页出现一次）
- 不做分段成绩、尾速计算
- 不做多维度综合评分（平稳度等），评分只按时间百分位
- 不做谷歌 / 百度地图接入，只用高德
- 不做摩托车 / 自行车逻辑（字段预留）
- 不做评论 / 路况提示的点赞、回复、图片
- （原「不做路线上传审核」已变更：产品化阶段已实现审核，见 §3.4）

## 8. 验收标准

1. 能看到路线列表（3 条 mock + 后续上传的），进详情页能看到地图轨迹和难度信息。
2. 能上传一条新路线（搜索规划或地图点选），提交后能在详情页看到自动算出的难度星级、弯道数等字段。
3. 能在路线详情页发一条评论和一条路况提示，刷新后能看到。
4. 点击开始跑山，选数据模式，到达终点或手动结束后，若选「参与算分」，结果页只显示分数和排名两个数字，界面上没有出现任何时间或速度数值。
5. 后端记录里能确认 `expiresAt` 字段设置正确；手动把某条记录的 `expiresAt` 改到过去，跑一次定时任务，确认 `rawTrackPoints` 被清空但 `score`/`rank` 保留。
6. 上传一条与已有路线高度重合的路线，能被查重提示；详情页能看到相似路线。
7. 以版主身份进入工作台，能审核本区待审路线；构造跨区审核请求会被拒绝。
8. 「我的」页面能看到资料、三项统计（成绩 / 路线 / 收藏）；未设昵称时显示派生名而非 openid。
