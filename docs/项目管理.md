## 一、七步开发模式（固定流程）

任何一项改动——新功能、改需求、修问题——都必须**顺序经过**这七步。步骤可以并行推进不同的事项，但**同一事项**不得跳步。

```
① 需求提出 ──▶ ② 产品设计 ──▶ ③ 代码实现 ──▶ ④ 单测&自验 ──▶ ⑤ 真机验证 ──▶ ⑥ 部署验证 ──▶ ⑦ 发布
   立项          定义形态          写代码          证明正确          证明能用          证明上得了线      交付
```

| 步骤 | 目标 | 入口条件（Gate） | 出口条件（Gate） | 主要产出 | 负责人角色 |
|---|---|---|---|---|---|
| ① 需求提出 | 说清「做什么、为什么」 | — | 需求条目进 SRS，验收标准明确 | SRS 条目 | 需求 / 产品 |
| ② 产品设计 | 说清「长什么样、怎么用」 | ① 通过 | 页面 / 交互 / 文案定稿 | 产品设计 章节 | 产品 / 设计 |
| ③ 代码实现 | 把设计变成代码 | ② 通过 | 代码可运行，接口连通 | 代码 + 架构设计更新 | 开发 |
| ④ 单测&自验 | 证明逻辑正确 | ③ 完成 | 单测通过；本地全流程自测通过 | 测试用例 + 自测记录 | 开发 |
| ⑤ 真机验证 | 证明在真手机上能用 | ④ 通过 | 真机（iOS+Android）主流程通过 | 真机验证记录 | 开发 / 测试 |
| ⑥ 部署验证 | 证明能上生产环境 | ⑤ 通过 | 云托管 + 云数据库联调通过 | 部署验证记录 | 运维 / 开发 |
| ⑦ 发布 | 交付给真实用户 | ⑥ 通过 | 提审通过并发布 | 发布记录 + 回滚方案 | 运维 |

### 状态词表（全表统一）

| 状态 | 含义 |
|---|---|
| **未开始** | 已登记，尚未动工 |
| **进行中** | 已动工，未完成 |
| **已完成** | 达到该步出口条件 |
| **阻塞** | 有外部依赖卡住，需在「备注」写明卡在哪 |
| **已取消** | 决定不做，需在「备注」写明原因（不删行，保留决策痕迹） |

### 表格维护约定

- **谁做谁更新**：事项进入某步骤时把状态改为「进行中」，完成时改「已完成」并填「更新时间」。
- **增删改**：新增一行即可，编号按步骤前缀递增（如 `I-13`）；不再做的事**改为「已取消」而非删除行**；重大变更在文末「变更记录」留一笔。
- **冲突处理**：同一行两人编辑时，以「更新时间」晚的为准；有争议在「备注」里写清楚，不要互相覆盖。
- **负责人填短名或 @昵称**，便于 search。

## 十、并行协作说明

七步是**同一事项的流水线**，不是全项目的串行关卡。多个事项可分别处在不同步骤，同时推进：

```
事项 A: ③ 代码实现 ──┐
事项 B:        ⑤ 真机验证 ──┐
事项 C:              ⑥ 部署验证 ──┐
事项 D:                    ② 产品设计 ← 新需求可随时进入
```

**当前并行态势**（2026-09-29）：

- 主线上（M6 上线）卡在 **⑤ 真机验证 → ⑥ 部署验证**，这是眼下的关键路径。
- ⑦ 发布的多数事项**阻塞在 L-02（AppID）**，需尽早启动，否则会拖住上线。
- 旁路可并行开的新事项：`T-09` 镜像算法一致性测试、`I-20` 版主申请接通、`T-10` 错误上报单测。

**关键路径提示**：`L-02 AppID → L-03 高德 Key → I-05 上传页真机可用 → L-06 提审`。AppID 与高德 Key 是有外部等待的环节，应优先启动。
